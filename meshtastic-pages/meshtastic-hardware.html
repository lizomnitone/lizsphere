What are LoRa and Meshtastic?

LoRa is a radio modulation (a "chirp spread spectrum" scheme, owned by Semtech) that trades data rate for range and weak-signal sensitivity. It is the physical layer only: it defines how bits become radio waves, not how devices find each other or route messages.

Meshtastic is open-source firmware that runs on LoRa hardware. It adds its own mesh networking, encryption and a phone-app interface on top of LoRa, so nodes can relay text messages and position data without cell service or Wi-Fi. It is not LoRaWAN, which is a different, gateway-based protocol from the LoRa Alliance. Hardware that works for one does not automatically run the other.

Throughput is low (roughly 1 kbps or less at the default long-range preset), which is why it suits short text and telemetry, not photos or voice.

How a LoRa radio node works (high level)

Almost every Meshtastic device is the same handful of blocks. Only the packaging changes.

  1. Antenna. Sets a large share of real-world range. A quarter-wave whip is roughly 8.2 cm at 915 MHz or 8.6 cm at 868 MHz in free space (real antennas are trimmed somewhat shorter). The antenna must match the band of the radio.
  2. RF front end. An impedance-matching network, filters to suppress harmonics, and an RF switch that connects the antenna to either the transmit or receive path. Some modules add an external power amplifier and/or low-noise amplifier.
  3. LoRa transceiver (SX1262/SX1268). Does the modulation and demodulation. It is controlled over SPI, plus a few extra lines: chip select, reset, a BUSY line, and an interrupt line (DIO1) that tells the microcontroller a packet arrived or finished sending.
  4. Frequency reference. LoRa needs a stable clock. Many modules use a temperature-compensated crystal oscillator (TCXO), which the SX126x can power through one of its pins.
  5. Microcontroller. Runs the firmware, mesh routing, encryption and phone interface (details below).
  6. Power. Usually a single-cell LiPo/Li-ion (about 3.0 to 4.2 V), a charger chip and a 3.3 V regulator. Receiving draws a few mA, but transmitting at high power draws on the order of 100 mA or more in short bursts, so a weak supply can cause brownouts or resets.
  7. Optional extras. GPS for position sharing, a small OLED or e-ink display, buttons, environmental sensors, a solar input.
Edge case: transmitting with no antenna (or a mismatched one) can damage the radio’s power amplifier on many modules. Attach the antenna before powering up.

Microcontrollers: what does it need to do?

  • Talk to the radio over SPI and handle its interrupt/BUSY lines.
  • Run the Meshtastic firmware: packet routing (flood-based relaying), a database of known nodes, and encryption. That needs a reasonable amount of flash and RAM.
  • Connect to a phone or computer via Bluetooth LE, USB serial or Wi-Fi, depending on the chip.
  • Provide extra interfaces: UART (GPS), I2C (display, sensors), spare GPIO (buttons, LEDs).
  • Sleep efficiently if it will run on a battery for days.
  • Support firmware updates (USB and/or over-the-air).

Frequency bands and regulations

Meshtastic is set to a regional band in firmware. Common examples are 902 to 928 MHz in the US and Canada (ISM), 863 to 870 MHz in much of Europe (EU868), and 433 MHz in some regions. Many boards are sold in band-specific variants (for example 433 / 868 / 915 MHz).

Check before transmitting: allowed bands, power limits and duty-cycle limits differ by country, and EU868 in particular has duty-cycle restrictions. Setting the wrong region, or using a board built for a different band, can be inefficient and in some places illegal. Rules change, so confirm with your local regulator.

Range vs. speed

LoRa lets you trade data rate for sensitivity using the spreading factor (SF) and bandwidth. Higher SF and narrower bandwidth give longer range but slower, longer-airtime transmissions. Meshtastic bundles these into presets (for example LongFast, which I believe uses SF11 with 250 kHz bandwidth, and LongSlow, which is slower and longer range). All nodes on a channel need to use the same preset to hear each other.

Real range depends mostly on line of sight, antenna height and quality, and terrain, far more than on the radio chip. Treat any single range number as a best case, not a guarantee.

Off-the-shelf vs. DIY

Buy a complete device

Easiest path: flash from the Meshtastic web flasher, pair with the phone app. Brands listed above make boards at several price and feature levels (bare boards, GPS trackers, e-ink handhelds, units with keyboards, solar nodes). Pick a device from the official supported list so the firmware has a matching hardware definition.

Build your own

  • Combine a supported MCU board with an SX126x module. Confirm the module’s band, voltage and pin requirements.
  • The firmware needs to know which pins connect to which radio signals. Arbitrary pinouts generally mean building custom firmware; a few generic "DIY" hardware definitions exist, so check the project docs first.
  • The Adafruit Feather M0 design linked above is a useful open example of how a LoRa board is laid out, but see the compatibility caveat below.
